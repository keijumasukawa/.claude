# コーディング規程

コードの記述方法を対象とし、言語を問わず適用する。

## 方針

- 関数は単一責任で小さく保つ。
- 業務判断の処理と、入出力・描画・フレームワーク依存の処理を分離する。
- 乱数・時刻等への依存は、引数として注入できる形に設計する。
- 外部入力はスキーマ検証を経て使用する。
- 共通の実装は一元管理し、重複定義しない。
- コメントは書かない。
- 型が不明な場合は `unknown` とし、型ガードで絞り込む。
- 状態・区分はユニオン型で表現する。
- 繰り返し現れる文字列リテラルは定数化する。

## 命名

言語の使い分けは文書規程による。

| 対象 | 書式 | 名称 |
| --- | --- | --- |
| 変数・引数・プロパティ | `camelCase` | 修飾語 + 名詞 |
| 真偽値 | `camelCase` | `is`・`has` + 状態 |
| 定数 | `UPPER_CASE` | 名詞 |
| 関数 | `camelCase` | 動詞 + 目的語。動詞は作用を表す語 |
| 型・クラス・enum | `PascalCase` | 名詞 |
| コンポーネント | `PascalCase` | 名詞 |
| フック | `camelCase` | `use` + 名詞 |
| state の設定関数 | `camelCase` | `set` + state 名 |
| イベントハンドラ | `camelCase` | プロパティ: `on` + 事象、実装: `handle` + 事象 |
| ファイル名 | `kebab-case` | 主名称 |

- フレームワーク固有の名称は公式仕様による。
- 外部ライブラリ由来の名前には適用しない。

関数の動詞は次による。該当する動詞がない場合は利用者に確認する。

| 区分 | 作用 | 動詞 |
| --- | --- | --- |
| 資源操作 | 取得 | `get` |
| 資源操作 | 一覧 | `list` |
| 資源操作 | 作成 | `create` |
| 資源操作 | 更新 | `update` |
| 資源操作 | 削除 | `delete` |
| その他 | 導出・算出 | `calculate` |
| その他 | 丸め | `round` |
| その他 | 正規化 | `normalize` |
| その他 | 変換 | `convert` |
| その他 | 整形 | `format` |
| その他 | 解析 | `parse` |
| その他 | 検証 | `validate` |
| その他 | 探索 | `find` |
| その他 | 構築 | `build` |
| その他 | 生成 | `generate` |
| その他 | 送信 | `send` |

## エラー

- 利用者に示すメッセージは、発生した事象と次に取る行動を示す。
- ステータスコードを利用者に示すメッセージとして用いない。
- 内部の構造を示す情報(接続先・ファイルパス・問い合わせ文・スタックトレース)を、利用者に示すメッセージに含めない。詳細はログに記録する。
