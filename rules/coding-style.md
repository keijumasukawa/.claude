# コーディング規程

「ツールへの委譲」「命名」「型の設計」は TypeScript プロジェクトを対象とする。「設計」「コメント」は言語を問わない。

## ツールへの委譲

書式および静的に検査できる規則は ESLint と Prettier に委譲し、本規程はツールで強制できない事項のみを定める。

ESLint と Prettier は公式の推奨設定をそのまま用い、個別の規則追加は行わない。
Lint ルールの無効化は、対象ファイル・対象ルールを限定して設定ファイル上で行い、コード中に無効化コメントを置かない。

## 命名

言語の使い分けは CLAUDE.md「記述言語」による。

| 対象 | 書式 | 品詞・語順 |
| --- | --- | --- |
| 変数・引数・プロパティ | `camelCase` | 修飾語 + 名詞 |
| 真偽値 | `camelCase` | `is`・`has` + 状態 |
| 定数 | `UPPER_CASE` | 名詞 |
| 関数 | `camelCase` | 動詞 + 目的語。動詞は `get`・`list`・`create`・`update`・`delete` |
| 型・クラス・enum | `PascalCase` | 名詞 |
| コンポーネント | `PascalCase` | 名詞 |
| フック | `camelCase` | `use` + 名詞 |
| state の設定関数 | `camelCase` | `set` + state 名 |
| イベントハンドラ | `camelCase` | プロパティ: `on` + 事象、実装: `handle` + 事象 |
| ファイル名 | `kebab-case` | 主名称 |

フレームワーク固有の名称は公式仕様による。外部ライブラリ由来の名前には適用しない。

## 型の設計

- 型が不明な場合は `unknown` とし、型ガードで絞り込む。
- 状態・区分はユニオン型で表現する。
- 繰り返し現れる文字列リテラルは定数化する。

## 設計

- 関数は単一責任で小さく保つ。
- 業務判断の処理と、入出力・描画・フレームワーク依存の処理を分離する。
- 層をまたいで共有する型は一元管理し、重複定義しない。
- 類似の既存実装があれば新規作成せず利用する。

## コメント

- コメントは書かない。コードで表現できない制約・前提の説明に限り認める。
- 変更履歴・作業メモ・コメントアウトした旧実装を残さない。
