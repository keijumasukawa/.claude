# コーディング規程

「ツールへの委譲」「命名」「型の設計」は TypeScript プロジェクトを対象とする。「設計」「コメント」は言語を問わない。

## ツールへの委譲

書式および静的に検査できる規則は ESLint と Prettier に委譲し、本規程はツールで強制できない事項のみを定める。

次の検査を ESLint の設定に含める。含まれていない場合は追加を提案する。本規程は検査の意図のみを定め、プラグイン・規則名は指定しない。

- 明示的な `any` の禁止
- オブジェクト形状の `interface` への統一
- ユニオン型に対する `switch` の網羅性検査
- 識別子の命名規則の強制(「命名」の節による)
- マジックナンバーの禁止
- named export への統一
- ファイル名の書式の強制(「命名」の節による)

フレームワークが `default export` や固有の命名を要求する場合は、対象を限定して設定ファイル上で除外する。
Lint ルールの無効化は、対象ファイル・対象ルールを限定して設定ファイル上で行い、コード中に無効化コメントを置かない。

## 命名

言語の使い分けは CLAUDE.md「記述言語」による。

- 変数・関数・引数・プロパティ: `camelCase`
- 型・クラス・enum: `PascalCase`
- モジュール直下で再代入しない定数: `UPPER_CASE` を認める
- ファイル名: `kebab-case`

## 型の設計

- 型が不明な場合は `unknown` とし、型ガードで絞り込む。
- 状態・区分はユニオン型で表現する。
- 繰り返し現れる文字列リテラルは定数化する。

## 設計

- 関数は単一責任で小さく保つ。
- 業務判断の処理と、入出力・描画・フレームワーク依存の処理を分離する。
- 層をまたいで共有する型は一元管理し、重複定義しない。
- 類似の既存実装があれば新規作成せず利用する。

## コメント

- コメントは書かない。コードで表現できない制約・前提の説明に限り認める。
- 変更履歴・作業メモ・コメントアウトした旧実装を残さない。
