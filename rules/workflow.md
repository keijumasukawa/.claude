# 作業手順規程

Claude Code による作業の進め方を定める。

## 承認

次の操作は実行前に内容を提示して承認を得る。可否の確認は選択式の質問で行う。設定で表現できる強制は `settings.json` の `ask` に置き、本規程は提示内容のみを定める。

- コミット — 変更内容の解説を提示する。
- ファイルの削除・既存内容の全面的な置換 — 対象と理由を明示する。
- 外部サービスへの送信・公開を伴う操作(リポジトリの内容、ログ、実行結果の送信等)。
  - Issue の作成・編集 — 本文の全文を提示する。
  - プルリクエストの作成・編集 — タイトルと本文の全文を提示する。
  - リリースの作成 — タグ名とリリースノートの全文を提示する。

作業ブランチの push は Git 運用規程の手順の一部として承認を要しない。テスト実行に伴う外部 API 呼び出しの例外はテスト規程「外部サービスの利用」による。

## Issue との紐付け

- 作業開始前に対応する Issue を確認する。存在しない場合は着手せず、作成を提案する。
- Issue は単独で完結する最小の作業単位で分割する。
- 例外は Git 運用規程に定める。

## コマンドの実行主体

- `ask` に置かれた操作は、承認を得て実行してよい。
- 上記以外の環境構築コマンド(データベースの初期化、外部サービスの設定等)は提示にとどめ、実行は利用者が行う。
- 状態を変更しない確認用コマンドは、作業上必要な範囲で実行してよい。
