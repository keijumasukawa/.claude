# テスト規程

テストの方針と手段を対象とし、言語・フレームワークを問わず適用する。

## 静的テスト

### 方針

- 書式及び静的に検査できる規則は ESLint と Prettier に委譲する。
- ESLint と Prettier は公式の推奨設定をそのまま用い、個別の規則追加を行わない。
- Lint ルールの無効化は、対象ファイル・対象ルールを限定して設定ファイル上で行う。

## 動的テスト

### 方針

- 新機能の追加とバグの修正には必ずテストを追加する。これは依頼範囲に含まれ、別途の承認を要しない。
- 実装の内部構造ではなく、外部から観測できる振る舞いをテストする。
- 各テストは実行順序に依存せず単独で成立させる。
- エンドツーエンドテストで本番データへの破壊的操作をしない。
- データを変更するテストは他への影響を検討し、必要に応じて直列実行とする。

### 配置・命名

- 単体・結合テストは、テスト対象と同じ階層には置かず、テスト用ディレクトリに置く。

| 対象 | 名称 |
| --- | --- |
| テスト用ディレクトリ | エコシステムの標準 |
| テストファイル | テスト対象と同名、接尾辞はエコシステムの標準 |
| テスト | テスト内容が判別できる日本語 |

### カバレッジ

- 計測時はカバレッジ値と未カバーのファイル・行を報告する。
- 数値の達成のみを目的としたテストを追加しない。
